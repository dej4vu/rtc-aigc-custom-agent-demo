一段文本，两条命运

第 4 课解决了浏览器消息。这一课回答最后一块能力协议：LLM 文本如何同时变成可听的 PCM 和可看的字幕，情感标签又为什么不能进入眼睛。

你将获得的小胜利

你能画出 SeedTTS 3.0 的请求契约、JSONL 事件流和文本双通道规则；也能判断无声音、有字无音、标签泄漏分别查哪一层。

一条语音句子的完整契约

LLM delta 经 SentenceSegmenter 成句后，TtsClient.synthesize() 发出 3.0 音色级流式请求：

POST https://voice.cn-beijing.volces.com/api/v3/text-to-speech/{voice_id}/streaming
X-Api-Key: <TTS_API_KEY>
X-Request-Id: <uuid>
Content-Type: application/json
{
  "text": "[happy] 你终于来啦。",
  "model_id": "doubao-seed-tts-3.0",
  "language_code": "zh",
  "enable_subtitle": true,
  "output_format": { "format": "pcm", "sample_rate": 24000 },
  "voice_settings": {
    "speed": 0.96,
    "pitch": 1,
    "instructions": ["甜软、亲密，轻声撒娇"]
  },
  "session_id": "同一 turn 的 UUID"
}

三个硬约束：pcm/24000 必须对应 MMPG pcm24；3.0 请求头不用 X-Api-Resource-Id；同一 turn 的多句共用 session_id 以稳定语气。

JSONL 事件流

event含义TtsClient / TurnController
ready流建立等待音频。
audioBase64 PCM解码为 Buffer；第一个 chunk 触发 tts.first_chunk 和 SPEAKING。
alignment字词时间戳经自定义消息分发，供字幕联动。
final本句完成本句 ended=true；是否发全局 done=true 仍由 turn 决定。
error错误与 request_id抛出错误；TurnController trace tts_error。

final 只表示一句 TTS 结束。只有 LLM 完成、TTS 队列为空、pending chunk 发出后，才向 MMPG 发送空 payload 的 assistant.audio.delta(done=true)。这是第 3 课 resp_id 所有权在 TTS 层的延续。

情感标签是调色板，不是台词

服务端把官方 82 个标签完整注入系统提示词：54 个情绪/语气控制标签，28 个副语言拟声标签。规则刻意克制：

  • 一次回复通常 1-2 个，最多 3 个。
  • 标签写在句首或情绪转折处；同一位置只能一个。
  • 禁止 [happy][soft] 连排；标签之间必须有正文。
  • 只允许官方英文拼写，不自造、不翻译、不用中文方括号。
  • 没有合适标签时宁可不加。

源码：server/lib/inline-tags.js:102。

双通道清洗规则

同一份 LLM 文本有两种用途：

  1. 语音通道：句子进入 enqueueTts() 前，用 sanitizeForSpeech() 删除 Markdown；官方标签保留，SeedTTS 自己消费。
  2. 可见通道：字幕、欢迎语展示和 LLM history 调用 stripInlineTags()；白名单标签删除，普通方括号文本保留。

stripInlineTags() 有一个重要流式细节：句尾出现 [so 或 [ 时，若它能匹配任何白名单标签前缀，就先隐藏，等下一个 delta 补齐后再判断。这防止用户短暂看到半个 [soft]。

源码：server/lib/inline-tags.js:140；测试：server/test/inline-tags.test.js:13。

字幕时间戳是第三条通道

请求默认 enable_subtitle:true，TTS 会返回 alignment。它不是主字幕本身，而是字词级时间元数据。前端通过 subt 自定义消息接收，并按 respId 与 Agent 字幕关联。当前实现已收集和展示这些时间戳，但还没有用它驱动逐字高亮；这是你改造语音 UI 的天然练习点。

源码：server/lib/tts-client.js:190、web/src/utils/handler.ts:147、web/src/pages/MainPage/MainArea/Room/Conversation.tsx:128。

  1. 打开 server/test/tts-client.test.js:84，列出测试断言的 URL、三个请求头、两个输出格式字段。

然后把实验台里的合法欢迎语改成：一个情绪标签 + 一句正文 + 一个副语言标签。注意不能连排，也不能在副语言标签后重复拟声词。把新文本发我。

开发方式迁移：模型能力不要散落拼字符串。把“官方标签清单、提示词约束、可见文本清洗”放在一个模块；把“URL、headers、请求体、JSONL 解码”放在客户端；把“是否完成播放”留给 TurnController。三层职责分开后，换音色、换 TTS 版本都不会污染轮次状态。
