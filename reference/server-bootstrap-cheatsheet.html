启动协议速查表

开发或排障时按「HTTP → 身份 → WebSocket → Session → Ready → Cleanup」检查。

对象边界

对象创建点生命周期关键字段
Page SessionPOST /getScenes页面短暂上下文SessionID、scenes
CallPOST /session/start一次真实通话roomId、userId、agentUserId、mmpg、controller
TurnASR done 或欢迎语一次回复respId、history、TTS queue、cancelled

启动顺序

  1. /getScenes 创建页面 Session。
  2. /session/start 校验配置并停掉旧 call。
  3. 生成 RoomId、UserId、AgentUserId 和 RTC Token。
  4. 实例化 TurnController，注入 Ark、TTS、MMPG 发送器。
  5. 绑定 event / gatewayError / gatewayClose。
  6. MmpgClient.connect() 使用 AK/SK 签名握手。
  7. createSession() 先挂 session.created waiter，再发 session.create。
  8. 成功后 store.setActiveCall()、controller.start()。
  9. 前端 Mic + Agent 双 ready 后发送一次 client.ready。
  10. 停止时先关 controller，再发 session.close 并关闭 WebSocket。

失败边界

  • 握手失败：查 AK/SK、URL、时间和网络。
  • 创建失败：catch 后 mmpg.close()，不要激活 call。
  • 网关关闭：controller 收到 error 后 stopCall。
  • 重复启动：用 startPromise 与旧 call 替换逻辑避免竞态。
  • 残留会话：看 /health 的 activeCalls。
