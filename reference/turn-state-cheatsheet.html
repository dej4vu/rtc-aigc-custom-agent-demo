Turn 状态机速查表

一条规则：resp_id 是音频所有权；AbortController 是任务所有权；TTS 队列是待播资产。

状态转移

输入事件条件结果
user.conversation.created无 active turn 且不是 SPEAKINGLISTENING
user.audio.transcription.started有未完成 turn取消旧 turn，进入 INTERRUPTED，递增 respId
user.audio.transcription.done文本非空push user message；创建 turn，进入 THINKING
LLM deltaturn 未取消累积文本、推送部分字幕、segmenter.push
第一个 TTS PCMturn 未取消进入 SPEAKING；发送 assistant.audio.delta
assistant.audio.doneresp_id 匹配清 activeTurn，进入 FINISHED
LLM / TTS 错误未被打断trace error；FINISHED stage；IDLE 状态

打断必须做的五件事

  1. 置 turn.cancelled = true，让迟到回调丢弃。
  2. 调用 turn.abort.abort()，取消 Ark fetch 和 TTS fetch。
  3. 清空 ttsQueue，防止旧句子继续合成。
  4. 把 respId 提升到旧值 + 1，旧音频事件全部失效。
  5. 发送 assistant.audio.cancel，让 Gateway 停止下行播放。

流式边界

  • ArkAgent：SSE 每行解析 data:，遇到 [DONE] 结束，delta 通过 onDelta() 回调。
  • SentenceSegmenter：硬断句符包括 。！？；…\n；闭合引号跟随前句；超过 80 字从软断句符附近截断。
  • TtsClient：3.0 走音色 streaming JSONL；ready/audio/final/error；Base64 PCM 解码后回调。
  • TurnController：TTS 任务串行 drain；最后一个 pending chunk 才发 done=true。

测试即规格

yarn --cwd server test turn-controller

  • 断言打断出现 assistant.audio.cancel、INTERRUPTED，新回复使用更高 resp_id。
  • 断言 [happy] 保留给 TTS，但字幕和历史消息被清洗。
